## Scope and recovery

- GitHub.com, existing project-linked repositories, already pushed base/head branches in that same repository. Cross-fork PRs are not supported in this slice. No local checkout, commit or push.
- Create requires an explicit draft choice. It first searches matching open PRs and reuses one without editing its content or draft state. Multiple candidates require explicit selection. Update requires an explicit PR number and matching repository/base/head; only title/body are changed, preserving draft state and branches.
- Official `gh api` uses explicit GET/POST/PATCH and JSON stdin. No shell interpolation, credentials copied to storage, or implicit local repository selection. Branch SHAs observed before a write and the actual returned PR SHAs are retained separately; branch movement is not presented as an atomic commit freeze.
- An identical caller/requestId/payload returns the existing operation. A different payload with that key is rejected. Two operations can execute globally, with one active operation per repository/head. History is bounded to 200 operations per task and 20 checks per operation.
- A missing write reply triggers a read check, never another write. Uncertain/restarted operations offer `github_pr_check`, which only reads GitHub and repairs the task link. A confirmed PR identity cannot be changed by a later selection. No matching PR remains unknown; a changed title/body cannot falsely confirm an update. A new explicit write requires a new request.
- Remote success and local association are separate facts. A failed link leaves the verified remote identity and a repairable result. Link, terminal record, activity and system mailbox message share one SQLite transaction. Repeated completion cannot duplicate notifications. Restart marks interrupted operations unknown and notifies once without replaying writes.
- MCP results notify the authenticated caller. GUI requests explicitly choose an Agent or task-only display. Existing mailbox/doorbell rules preserve messages for closed/offline Agents without forcing a wakeup. The notification includes the task, operation and PR reference; it grants no merge/review/task-done authority.
- The task panel refreshes the entire loaded history range, preserving expanded content and pagination. Full submitted/observed bodies and check history are loaded on demand. Each retained detail has an explicit refresh action. Existing GitHub links refresh after a successful association; CI remains unknown until the existing GitHub refresh observes it.

## Validation

Independent R1 found that a numbered update interrupted with `remote=null` could accept another matching historical PR during recovery. Store admission and remote reconciliation now preserve the original explicit number, while unnumbered create operations retain candidate selection. The new regression failed against the R1 candidate, then all nine PR-operation tests passed after the fix. It covers actual Store reopen, rejection without a new notification or link, the independent worker guard, unknown content on the original target, and successful read-only recovery once that original target matches; all remote calls remain GET and the alternate PR is never read. This point fix does not repeat the full local matrix or real GitHub/model acceptance.

Changed operation state labels cached detail as outdated until explicitly refreshed. Existing three GitHub-link and five review UI regressions pass. Production UI typecheck/build pass. The Core library run passed 262 tests with three explicitly ignored native/private-fixture tests; the remaining five Unix-socket tests passed with a short private temporary path (267 total passing).
