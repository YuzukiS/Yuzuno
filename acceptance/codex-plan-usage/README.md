# T-83 Codex account plan usage

Source baseline: `4ee12e2fe8b9790785648a005561ea4c7b577148`. Independent worktree `t83-codex-plan-usage`, branch `feat/t83-codex-plan-usage`. Merged source is not an installed feature.

The Agent information list has compact Account and Plan usage rows, manual refresh and keyboard-accessible details. Values are account-wide native observations, never per-Agent allocations or inferred token costs. Window names/durations come from Codex; missing values stay unknown. A passed reset deadline means waiting for another report. Five-minute-old windows are labelled last report; each window keeps its own observation time through sparse updates. Errors retain dated observations and explicitly say refresh failed.

Core reads only `account/read` (`refreshToken:false`) and `account/rateLimits/read` on the Agent's existing native connection. It never starts/attaches a thread or reuses the catalog account for remote Agents. Provenance contains connection generation, machine/runtime and backend accountId when supplied. Authentication changes and replacement clear data and invalidate in-flight answers. Rolling notifications merge only into a verified snapshot on that generation. They have no accountId, so cross-connection sharing is deliberately absent. Cache reads are bounded at 60 seconds; explicit requests coalesce with a 5-second minimum interval. There is no native polling loop. Lightweight `agent.codexUsage` SSE updates never read conversations or mark them read.

Protocol basis: installed `codex-cli 0.162.1`, matching generated TypeScript schemas, and [official App Server docs](https://learn.chatgpt.com/docs/app-server). The native probe uses a new read-only stdio process and existing authentication, makes no model call, and writes only allowlisted/redacted fields; it does not read credential files itself. Fixtures cover failure/unsupported/API key/unknown/multi-bucket/sparse/generation races. A local probe does not prove remote-account behavior.

Run `validate.sh` through a bounded Yuzuno Job and heavy-slot helper. Data, builds, screenshots and logs stay isolated. `T83_NATIVE=1` adds the read-only native probe. Chromium renders the production component with fixture transport at an ephemeral localhost port; it never operates the daily window. Exact Jobs, results, failures, CI and review IDs are retained on T-83.
